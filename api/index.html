Ultimatrix clock API (0.9.0)

Download OpenAPI specification:

License: See LICENSE in the repository

The HTTP API of an Ultimatrix LED clock (ESP32, 64x64 HUB75 panel). It is what the clock's own settings page (/) uses, so everything the page can do is available here. Not every route exists in every build: faces are compiled in or out (the Pac-Man, Pong, Invaders, NFL and game-controller routes are the main ones), and the WLED routes are not in the bridge image.

Calling it

  • The clock answers on port 80, by IP address or .local name. There is no TLS.
  • POST routes read their parameters as a form (application/x-www-form-urlencoded) or as query-string parameters; both work. The WLED, canvas-frame and timer routes take a JSON body instead (marked below).
  • Booleans in forms are mostly sent as 1/0, or by the field being present (checkbox style); each field says which.

Access rules (all routes)

  • 403 for clients outside the allowed network (setting accessScope) and for public host names (a name under a real top-level domain) unless anyHost is set. Open the clock by IP or .local.
  • POST bodies over 8192 bytes get 413. A POST carrying an Origin header for another host gets 403 (a web page on another site cannot drive the clock). Requests without Origin (curl, Home Assistant, the WLED app) pass.
  • If an admin PIN is set, POST routes need an X-Token header (from POST /api/auth) and answer 401 with {"message":"Enter the clock PIN.","pin":true} without it. These stay open: /api/auth, /api/ha/detect, /json, /json/state, /dlna/*, /api/wled*, /api/canvas/*.

Verification. The routes, parameters, ranges and status codes come from reading the firmware (firmware/src/main.cpp, lib/wled/*, lib/core/*). Nothing here was machine-checked against a running clock except /api/dim-colour, /api/hue-test, /api/screen, /api/display and /api/settings. Large response bodies (settings, Home Assistant configuration, sports schedule) list their fields but not every nested detail.

Dim-colour settings

How the driver shows very dim colours. A HUB75 panel cannot show every shade at low brightness, so a dim colour can round to black in one channel and change hue (a dim orange turns red, a dim grey turns pink). Three optional corrections exist: the hue guard (guard, on by default) lifts pixels that would round to black while keeping their hue; the search (search, off by default) looks for the closest reachable colour; and the weights (wg to bb) tell the search how strong the red, green and blue LEDs of your panel are. The weights depend on the panel; firmware/tools/colour-calibrate.py finds them. The calibration dialog in Settings uses floor and night. /api/hue-test shows test patches while you tune.

Change dim-colour settings

Send any of the fields. By default the result is stored in flash. With save=0 it applies only until the next restart. reset=1 restores the defaults but keeps the calibrated floor and the night level. The answer is the new state.

Authorizations:
NonepinToken
Request Body schema: application/x-www-form-urlencoded
search
integer
Default: 0
Enum: 0 1

Off by default. 1 turns on the dim-colour search: for very dim pixels it tries nearby combinations of the red, green and blue light levels and picks the one that looks closest to the wanted colour, using the weights below to correct for how the LEDs differ in strength

guard
integer
Default: 1
Enum: 0 1

Hue guard; lifts pixels that would round to black, keeping the hue. On by default. Only acts below the pulse-width floor (about panel brightness 137/255), on pixels whose channels all round to level 1 or less

restore
integer
Default: 1
Enum: 0 1

After the weights have shifted a dim colour, scale it back so it is about as bright as the original. Only matters when search is on

brightness
number [ 0.01 .. 9.99 ]
Default: 0.06

How much the search cares about getting the brightness right compared with the hue. Higher keeps brightness, lower favours the exact colour

extra
integer [ 1 .. 8 ]
Default: 2

How many light levels above the wanted one the search may use for a channel when it looks for a better match

limit
integer [ 4 .. 40 ]
Default: 8

The search only runs for pixels whose brightest channel is at or below this many plane weights (the panel shows light in bit planes; a higher value covers brighter pixels)

guardMin
number [ 0 .. 3.9 ]
Default: 0

Lowest light, in plane weights, the hue guard still lifts. 0 (default) lifts every non-black pixel; a higher value leaves very dark pixels black. Stored in 1/64 steps

floor
integer [ 0 .. 200 ]
Default: 0

Lowest panel brightness (0-255) found by the colour calibration, where all colours still show. The Minimum brightness slider stretches over the range from here upwards. 0 = no calibration

night
integer [ 0 .. 255 ]
Default: 31

Panel brightness (0-254) used in night mode; 31 is about 12 %. 0 = panel dark

wg
number [ 0.1 .. 5 ]
Default: 1

Green weight for reds and ambers (red leads). Above 1 adds green to a dim red/amber/orange; 1 = neutral

wb
number [ 0.1 .. 5 ]
Default: 1

Blue weight for reds and ambers (red leads). Above 1 adds blue; 1 = neutral

gg
number [ 0.1 .. 5 ]
Default: 1

Green weight for greys and whites (no saturation). Blends towards wg as the colour gets more saturated; 1 = neutral

gb
number [ 0.1 .. 5 ]
Default: 1

Blue weight for greys and whites. Blends towards wb as the colour gets more saturated; 1 = neutral

og
number [ 0.1 .. 5 ]
Default: 1

Green weight when green leads (green, teal and their pastels); below 1 thins out the green that the red LED would otherwise dominate; 1 = neutral

ob
number [ 0.1 .. 5 ]
Default: 1

Blue weight when green leads (green, teal and their pastels); 1 = neutral

bg
number [ 0.1 .. 5 ]
Default: 1

Green weight when blue leads (blue, cyan and their pastels); 1 = neutral

bb
number [ 0.1 .. 5 ]
Default: 1

Blue weight when blue leads (blue, cyan and their pastels); below 1 takes the violet out of a blue; 1 = neutral

save
integer
Default: 1
Enum: 0 1

0 = apply until restart only

reset
integer
Enum: 0 1

1 = restore defaults first

Show the colour test grid

Shows a grid of swatches on the panel at a chosen brightness: 8 hues x 8 columns of 100, 70, 50, 35, 25, 18, 12 and 8 % of full colour (16 hue rows with wide=1). It ends after secs (at most 600), or at once with b=0. Optional tuning arguments change the driver live and are not stored. Read the result back with GET /api/screen.
